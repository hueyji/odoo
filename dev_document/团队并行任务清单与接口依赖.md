# 并行开发团队任务清单与接口依赖

> 目标：为 Team A–G 制定可执行的交付清单与接口依赖，支撑并行开发。所有接口统一收录在 `dev_document/postman_collection/brand_store_suite.postman_collection.json` 中；如需新增接口，需同步更新该集合并在本文件登记依赖关系。

> 最新接口契约、联调脚本参见：`dev_document/协调机制与接口里程碑.md`，演示数据脚本 `dev_document/scripts/seed_interface_data.py`。

---

## 自研模块 manifest 基线（Odoo 16.0）

| 模块 | 命名空间 | 依赖模块（按安装顺序） | 说明 |
| --- | --- | --- | --- |
| `brand_core` | `brand_core` | `base`, `mail`, `contacts`, `portal`, `auth_signup` | 多公司骨架、互通组、门户兜底；不依赖 17+/18+ UI 特性 |
| `store_inventory` | `store_inventory` | `stock`, `uom`, `mail`, `brand_core` | 扩展 `stock.move/quant` 与批次模型，沿用 16 资产体系 |
| `store_supplier` | `store_supplier` | `purchase`, `mail`, `brand_core` | 门店供应商档案、评分；复用 16 `purchase` 工作流 |
| `store_commission` | `store_commission` | `sale_management`, `hr`, `mail`, `brand_core` | 提成规则引擎，使用 16 `sale.order` API (`action_confirm`) |
| `store_performance` | `store_performance` | `store_commission`, `hr`, `mail` | 个人/门店业绩看板，依赖提成日志 |
| `store_finance` | `store_finance` | `account`, `mail`, `brand_core` | 自研流水模型，使用 16 `account.move` / `account.payment.register` |
| `store_member` | `store_member` | `contacts`, `portal`, `mail`, `brand_core`, `store_finance` | 会员档案、余额、Portal；兼容 16 Portal Bootstrap 模板 |
| `store_bar` | `store_bar` | `point_of_sale`, `pos_hr`, `mail`, `store_inventory`, `store_commission`, `store_member` | 吧台点单/桌台，保持 POS 16 组件接口 |
| `store_crowdfunding` | `store_crowdfunding` | `mail`, `brand_core`, `store_finance`, `store_member` | 众筹项目与分红流程，复用 16 `mail.activity` |

- 自研模块统一前缀 `store_`/`brand_`，避免与 Odoo 核心冲突。  
- JS / SCSS 资产通过 `__manifest__.py` 的 `assets` 注册，命名空间 `brand_store_*`，禁止引用 17+/18+ 新增的 `@odoo/hoot`、`spreadsheet_dashboard_*`。  
- 如需新增模块依赖，需在 Tech Review 前更新此表并说明与 16 版核心的兼容性。

## Team A 平台基建组（`brand_core` + 互通基础）

### 核心交付清单
- [ ] 多公司初始化脚本与配置向导（品牌总部/门店/投资人虚拟公司）  
- [ ] 互通组模型与审批：`store.link.group`、申请审批、共享范围配置  
- [ ] 权限基线：多公司 ir.rule、互通补充规则、门户访问控制  
- [ ] 角色映射与 ACL 测试：组定义、访问控制列表、单元测试  
- [ ] Demo 数据与配置检查器：门店、老板、互通组、陈化仓校验

### 接口依赖
- **对外提供**
  - `GET /api/link-groups`：互通组列表（提供给 Team B/E/G 做权限判断）  
  - `POST /api/link-groups/apply`：门店发起互通申请（Team E 门店界面调用）  
  - `PATCH /api/link-groups/{id}`：品牌审批结果同步（Team G 需写入审批日志）  
  - `GET /api/companies/tree`：公司树结构（Team D/F 获取公司→门店映射）
- **对内依赖**
  - Team B：批次库存状态用于配置检查器检测仓库  
  - Team D：财务科目与渠道信息用于公司初始化默认值  
  - Team E：需要会员字段定义对接 Portal 权限

## Team B 库存与供应链组（`store_inventory` + `store_supplier`）

### 核心交付清单
- [ ] 批次库存模型 `store.inventory.batch` 与 `stock.move/quant` 扩展  
- [ ] 入库、盘点、报损、调拨流程及审批链  
- [ ] 陈化管理：陈化天数计算、定时任务、看板（OWL）、导出  
- [ ] 供应商管理：档案/评分/黑名单、合同附件、采购历史报表  
- [ ] 集成测试与 Demo 数据：多公司批次操作、互通调拨样例

### 接口依赖
- **对外提供**
  - `POST /api/inventory/batches`：创建批次（Team D 提成成本校验、Team F 点单校验）  
  - `GET /api/inventory/batches/{id}`：批次详情含陈化信息（Team F 点单、Team E 会员推荐）  
  - `POST /api/inventory/transfers`：互通调拨申请（Team A 权限校验、Team D 财务补差）

- **对内依赖**
  - Team A：互通组权限与审批结果  
  - Team C：责任员工信息（点单时绑定）  
  - Team D：财务结算，入库/报损需同步流水  
  - Team F：点单指令触发扣减批次

## 接口文档与集合维护约定

- Postman 集合路径：`dev_document/postman_collection/brand_store_suite.postman_collection.json`  
- 环境变量模板：`dev_document/postman_collection/env_odoo16_template.postman_environment.json`（同步于 16.0 基线）  
- 更新流程：新增/调整接口 → 在集合中编写请求示例 → 在本文件对应团队的“对外提供”/“对内依赖”条目同步说明 → 提交 PR 时附带集合差异。  
- QA 校验：接口自动化测试脚本统一放入 `addons-custom/<module>/tests/test_api_*.py`，确保集合示例可直接复现。  
- 文档更新责任：各团队 Tech Lead 每周会前确认集合与清单同步，无差异后再发出测试或验收邀请。
