# 接口契约模板（Odoo 16.0 多门店项目）

> 适用范围：品牌多门店项目 Team A–G 所有 REST/Controller 接口。新接口或字段调整前必须复制以下模板，提交至 `dev_document` 对应模块目录，并在 PR 描述中引用。  
> 版本：v1.0（2025-11-05） 责任人：平台基建组 / 接口协调 PM。

---

## 1. REST 命名空间与版本规范

- **基础路径**：`https://{host}/api/v1/{域模块}/{资源}`。`域模块` 优先使用团队首字母（`link`、`inventory`、`finance` 等），避免重复。  
- **HTTP 方法**：遵循语义化约定（`GET` 查询、`POST` 新增、`PATCH` 局部更新、`DELETE` 作废/撤销）。  
- **资源命名**：复数英文蛇形（如 `link-groups`、`commission-logs`），与 Odoo 模型字段保持一致。  
- **请求格式**：默认 `application/json; charset=utf-8`。需要文件上传时使用 `multipart/form-data`，必须在契约中单独说明。  
- **认证头**：默认 `Cookie: session_id={{session_id}}`（Odoo Session 模式）；若使用 API Key，则为 `Authorization: Bearer {token}`。认证策略参见 `dev_document/API认证与权限策略.md`。  
- **分页参数**：统一 `limit`（默认 20，最大 200）、`offset`；排序使用 `order=field asc/desc`。  
- **时间字段**：返回 ISO8601（UTC），如需门店本地时间需额外提供 `tz_offset`。  
- **布尔/枚举**：布尔字段使用 `true/false`，枚举统一小写蛇形，与模型 `selection` 完全一致。  
- **字段翻译**：返回体的 `display_name_cn`、`message_cn` 等需提供中文说明，必要时附英文字段帮助注释。

## 2. 接口契约文档模板

```markdown
### {团队}/{模块} - {接口名称中文}

- **URL**：`/api/v1/{domain}/{resource}`  
- **Method**：`GET|POST|PATCH|DELETE`  
- **鉴权**：`Cookie: session_id={{session_id}}`（角色：{res.groups 名称}）  
- **幂等性标识**：（如需要 `X-Idempotency-Key`，注明 Header 与校验规则）  
- **调用前置条件**：示例：已创建互通组、批次状态=`available`、会员余额≥0 等。

#### 请求参数
| 字段 | 类型 | 必填 | 说明（中文） | 示例 |
| --- | --- | --- | --- | --- |
|  |  |  |  |  |

#### 返回体
```json
{
  "data": { ... },
  "meta": { ... },
  "warning": null
}
```
> 必须列举关键字段，并标注中文含义及取值范围。

#### 错误码
| 错误码 | HTTP | 中文提示 | 说明 | 建议动作 |
| --- | --- | --- | --- | --- |
|  |  |  |  |  |

#### 事件 / 回调
- 示例：触发 `bus.bus` 渠道 `commission.notify`，消息体结构 `{order_id, employee_ids}`。

#### 测试用例
- Postman 请求：`dev_document/postman_collection/brand_store_suite.postman_collection.json` → `{文件夹路径}`。  
- 演示数据：`dev_document/scripts/seed_interface_data.py` 输出变量 `{变量名}`。
```

## 3. 错误码结构（必填字段）

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| `code` | 业务错误码，格式 `TEAMA_0001`，团队简称 + 4 位编号 | `TEAMB_0203` |
| `http_status` | HTTP 状态码 | `400` |
| `message_cn` | 中文用户提示，需直观说明 | `库存批次不可用，请刷新后重试` |
| `message_en` | 英文技术提示（可选） | `Inventory batch is not available.` |
| `details` | 字段级错误/调试信息数组 | `[{\"field\": \"qty\", \"reason\": \"不足\"}]` |
| `trace_id` | 请求跟踪号，来自 `ir.logging` | `REQ-20251105-000123` |

错误码区段预留（避免冲突）：

- Team A：`TEAMA_0001`–`TEAMA_0499`  
- Team B：`TEAMB_0500`–`TEAMB_0999`  
- Team C：`TEAMC_1000`–`TEAMC_1499`  
- Team D：`TEAMD_1500`–`TEAMD_1999`  
- Team E：`TEAME_2000`–`TEAME_2499`  
- Team F：`TEAMF_2500`–`TEAMF_2999`  
- Team G：`TEAMG_3000`–`TEAMG_3499`

## 4. 接口验收工单模板（Stand-up 必查）

> 所有跨团队接口在联调或上线前需提交验收工单，存档于共享表单或 `Notion/Excel`。Stand-up 由 Tech Lead 根据此模板逐项过检。

| 字段 | 填写说明 |
| --- | --- |
| 接口名称/版本 | 例：`POST /api/v1/inventory/transfers` v1.0 |
| 需求背景 | 简述业务场景、触发条件 |
| 输入数据 | 演示数据 ID、关键字段取值、调用顺序 |
| 预期响应 | 样例响应片段、关键字段说明 |
| 依赖接口/模块 | 需提前完成的接口或脚本 |
| 权限角色 | 哪些用户组需要验证 |
| 联调步骤 | Step1 调用xx → Step2 校验xx → Step3 回调/通知 |
| 异常用例 | 至少 2 条（权限不足、数据不合法等） |
| 日志与监控 | Odoo 日志、`ir.logging` Trace ID、Bus 渠道订阅 |
| 验收结果 | `通过/阻塞` + 经办人（中文名） + 日期 |

---

## 5. 流程要求

1. 新接口/重大变更 → 使用本模板撰写 → 提交 MR/PR 并 @ 跨团队接口协调人。  
2. PR 合并前必须同步更新 Postman 集合与 `seed_interface_data.py`，确保 Demo 可复现。  
3. 里程碑周（M1/M2/M3）前 2 个工作日，平台基建组将审核所有开放工单并在 Stand-up 上确认收口状态。  
4. 所有模板版本变更需记录在 `PLAN.md` 备注，便于回溯。
