# Odoo 16 财务流水生成策略（Team D）

## 1. 与 `account.payment.register` 的差异
- `account.payment.register` 面向发票支付场景，默认要求存在 `account.move`（客户/供应商发票）记录，流程较重且会触发应收应付科目。 
- 门店流水多来自点单、互通调拨、充值等运营事件，不一定存在发票，强制走 Payment Register 会产生多余的会计凭证。 
- Payment Register 会自动创建 `account.payment`，进而生成银行分录；我们只需记录运营流水并可选对接正式会计，因此改用轻量模型管理。 

## 2. 采用自研 `store.account.transaction` 的策略
- 以运营事件为核心：通过模型字段直接绑定订单、库存、众筹等来源，保障闭环。 
- 通过 `store.finance.account.map` 映射各类型流水需要使用的会计科目，必要时再生成 `account.move`。 
- 互通清算流程使用 `store.finance.clearing` 聚合多笔流水，与品牌总部账期、互通门店结算保持一致。 

## 3. 需要对接正式会计时的推荐流程
1. 由财务经理配置 `store.finance.account.map`，确定各类流水的默认科目与日记账。 
2. 清算或日结时，通过按钮/批处理调用服务： 
   - 根据流水类型生成合并凭证（`account.move`），借贷使用映射科目； 
   - 若涉及支付渠道资金变动，可同步创建 `account.payment` 并关联到 `account.move`。 
3. 记录生成的 `account.move` 在 `store.account.transaction.account_move_id` 字段，确保可追溯。 

## 4. 后续扩展建议
- 若部分门店已启用标准发票流程，可在接口层增加参数，允许直接指向既有的 `account.move`。 
- 补充清算审核/导出 Excel 功能，满足总部审计需求。 
- 结合 Team B/G 的库存补差与众筹入账场景，保持科目映射的一致性（见数据初始化中的 `transfer_adjust`、`crowdfunding_invest`、`crowdfunding_dividend` 科目）。 

## 5. 当前实现进展（2025-11-02）
- 已为 `store.finance.clearing` 增加审核人、审核时间及“审核通过”状态，实现草稿→待审核→已审核→取消的完整流程；取消时自动解除流水关联。 
- 新增 `/api/v1/finance/transactions`、`/api/v1/finance/clearing`、`/api/v1/finance/clearing/<id>/approve` 与 `/api/v1/finance/clearing/<id>/export` 接口，分别支持流水查询/写入、清算创建、审核通过及 Excel 导出，均基于财务权限组鉴权。 
- `互通清算` 导出文件内含清单与汇总信息表，便于总部对账与归档；导出采用公司本币金额并附带渠道、原币金额等关键字段。 
- 自动化测试覆盖交易写入、权限拒绝、清算创建/导出/审核流程，确保接口行为稳定。
