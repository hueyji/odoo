> 目标：总结开发过程中频繁出现的错误模式，帮助开发者避免重复踩坑，提高代码质量和系统稳定性。

## 1. Assets 路径错误

### 错误表现
```
ValueError: 'addons-custom/store_inventory/static/src/xml/aging_dashboard.xml'文件中缺少模板名称。
```

### 根本原因
在 `__manifest__.py` 的 `assets` 配置中使用了错误的路径前缀。

**错误写法**：
```python
"assets": {
    "web.assets_backend": [
        "addons-custom/store_inventory/static/src/js/aging_dashboard.js",
        "addons-custom/store_inventory/static/src/xml/aging_dashboard.xml",
    ],
},
```

**正确写法**：
```python
"assets": {
    "web.assets_backend": [
        "store_inventory/static/src/js/aging_dashboard.js",
        "store_inventory/static/src/xml/aging_dashboard.xml",
    ],
},
```

### 预防措施
1. ✅ **Assets 路径必须使用模块相对路径**，不要包含 `addons-custom/` 或 `addons/` 前缀
2. ✅ 路径格式：`<module_name>/static/src/<type>/<filename>`
3. ✅ 提交前检查：`grep -r "addons-custom/" */manifest.py` 应该返回空结果

## 2. 启动脚本硬编码参数覆盖配置文件

### 错误表现
```
UncaughtPromiseError: Cannot read properties of undefined (reading 'relation')
```
模块明明已安装，但前端无法加载模块的字段定义。

### 根本原因
启动脚本（如 `odooctl.sh`）中硬编码了 `--addons-path` 参数，覆盖了 `odoo.conf` 中的正确配置。

**错误示例**（odooctl.sh）：
```bash
nohup "$PYTHON_BIN" "$ODOO_DIR/odoo-bin" \
    -c "$CONFIG_FILE" \
    --addons-path="$ODOO_DIR/odoo/addons,$ODOO_DIR/addons" \  # ❌ 缺少 addons-custom
    ...
```

**正确做法**：
```bash
nohup "$PYTHON_BIN" "$ODOO_DIR/odoo-bin" \
    -c "$CONFIG_FILE" \
    -d "$DB_NAME" \
    ...
    # ✅ 不要硬编码 --addons-path，让 Odoo 使用配置文件
```

### 预防措施
1. ✅ **启动脚本不要硬编码 `--addons-path`、`--db-filter` 等关键参数**
2. ✅ 所有路径配置统一写在 `odoo.conf` 中
3. ✅ 启动后检查日志：`grep "addons paths" odoo.log` 确认包含所有自定义模块目录
4. ✅ 代码审查清单：检查所有 `.sh` 脚本是否有硬编码参数

## 3. 数据库中的"幽灵"附件记录

### 错误表现
```
FileNotFoundError: [Errno 2] No such file or directory: 
'/path/to/filestore/odoo16/d0/d09086a0794cf3070f12e742f27126254b4e2b5a'
```

反复清除缓存、重启服务后错误依然存在。

### 根本原因
数据库中的 `ir_attachment` 表有记录指向已删除的物理文件，常见场景：
- 手动删除了 filestore 目录中的文件
- 数据库恢复后 filestore 没有同步
- 开发过程中清理缓存时误删了文件
- **浏览器不断重试加载 favicon 等资源，导致损坏记录被重新创建**

### 解决方案

#### 方法1：查找并删除损坏的附件（推荐）
```python
import os
import odoo
from odoo import api, SUPERUSER_ID

db_name = 'odoo16'
odoo.tools.config.parse_config(['--config=odoo.conf'])

with odoo.api.Environment.manage():
    registry = odoo.registry(db_name)
    with registry.cursor() as cr:
        env = api.Environment(cr, SUPERUSER_ID, {})
        
        # 查找所有 filestore 附件
        attachments = env['ir.attachment'].search([
            ('store_fname', '!=', False)
        ])
        
        filestore_path = '/path/to/.odoo-data/filestore/odoo16'
        broken_ids = []
        
        for att in attachments:
            full_path = os.path.join(filestore_path, att.store_fname)
            if not os.path.exists(full_path):
                broken_ids.append(att.id)
                print(f"损坏: ID={att.id}, Name={att.name}, File={att.store_fname}")
        
        if broken_ids:
            env['ir.attachment'].browse(broken_ids).unlink()
            print(f"已删除 {len(broken_ids)} 个损坏的附件")
        
        cr.commit()
```

#### 方法2：精确定位特定文件的引用
```python
# 如果知道具体的文件哈希
missing_file = 'd0/d09086a0794cf3070f12e742f27126254b4e2b5a'

cr.execute("""
    SELECT id, name, res_model, res_id, res_field
    FROM ir_attachment
    WHERE store_fname = %s
""", (missing_file,))

for att in cr.fetchall():
    print(f"ID: {att[0]}, Model: {att[2]}, ResID: {att[3]}, Field: {att[4]}")

# 删除这些记录
cr.execute("DELETE FROM ir_attachment WHERE store_fname = %s", (missing_file,))
cr.commit()
```

### 预防措施
1. ✅ **不要手动删除 filestore 目录中的文件**
2. ✅ 数据库恢复时必须同步恢复 filestore 目录
3. ✅ 定期运行附件完整性检查脚本（建议加入 CI/CD）
4. ✅ 开发环境清理缓存时使用 `./odooctl.sh clean assets`，不要直接删除 filestore
5. ✅ 浏览器测试时清除缓存，避免不断重试加载损坏的资源

## 4. 自定义 SCSS/Assets 引用不存在的文件

### 错误表现
```
Style error: Could not get content for 
/website/static/src/scss/options/user_values.custom.web.assets_frontend.scss
```

### 根本原因
数据库中的 `ir.asset` 表有记录引用了不存在的自定义样式文件，通常是：
- 之前自定义了网站主题，后来删除了相关文件
- 数据库中保留了对这些自定义样式的引用
- 清除缓存无法解决，因为 Odoo 每次启动都会从 `ir.asset` 表读取

### 解决方案
```python
# 查找问题记录
cr.execute("""
    SELECT id, name, path
    FROM ir_asset
    WHERE path LIKE '%user_values.custom%' 
       OR path LIKE '%user_theme_color_palette.custom%'
""")

for record in cr.fetchall():
    print(f"ID: {record[0]}, Name: {record[1]}, Path: {record[2]}")

# 删除这些记录
cr.execute("""
    DELETE FROM ir_asset
    WHERE path LIKE '%user_values.custom%' 
       OR path LIKE '%user_theme_color_palette.custom%'
""")
cr.commit()
```

### 预防措施
1. ✅ **自定义网站主题时使用 Odoo 的主题编辑器**，不要手动创建 SCSS 文件
2. ✅ 删除自定义主题前，先在后台"网站 → 配置 → 主题"中卸载
3. ✅ 清除缓存后如果错误依然存在，检查 `ir.asset` 表
4. ✅ 代码审查：检查是否有直接操作 `ir.asset` 的代码

## 5. 模块加载顺序和依赖问题

### 错误表现
- 字段未定义错误
- 视图找不到模型
- 权限组不存在

### 根本原因
`__manifest__.py` 中的 `depends` 列表不完整或顺序错误。

### 预防措施
1. ✅ **依赖声明原则**：
   - 使用了其他模块的模型 → 必须在 `depends` 中声明
   - 继承了其他模块的视图 → 必须在 `depends` 中声明
   - 使用了其他模块的权限组 → 必须在 `depends` 中声明

2. ✅ **常见依赖**：
   ```python
   "depends": [
       "base",           # 基础模型（res.partner, res.company）
       "mail",           # 消息和活动（mail.thread, mail.activity）
       "stock",          # 库存管理
       "sale",           # 销售订单
       "account",        # 财务会计
       "hr",             # 人力资源
       "website",        # 网站功能
       "portal",         # 门户访问
   ],
   ```

3. ✅ **检查方法**：
   ```bash
   # 查找模型引用
   grep -r "env\['sale.order'\]" addons-custom/your_module/
   # 如果有结果，确保 depends 包含 'sale'
   
   # 查找视图继承
   grep -r 'inherit_id.*ref' addons-custom/your_module/views/
   # 检查引用的模块是否在 depends 中
   ```

## 6. 字段定义与视图不匹配

### 错误表现
- 前端显示 "Field xxx does not exist"
- 保存时提示字段不存在

### 常见错误
1. **字段名拼写错误**：模型中是 `member_level_id`，视图中写成 `member_level`
2. **字段类型不匹配**：Many2one 字段在视图中缺少 `_id` 后缀
3. **计算字段未设置 store**：需要在视图中显示的计算字段必须 `store=True`

### 预防措施
1. ✅ **命名规范**：
   - Many2one/Many2many 字段必须以 `_id` 或 `_ids` 结尾
   - Boolean 字段建议以 `is_`、`has_`、`enable_` 开头
   - Selection 字段建议以 `_state`、`_type`、`_status` 结尾

2. ✅ **视图开发流程**：
   - 先定义模型字段
   - 升级模块：`./odooctl.sh start -u module_name`
   - 在数据库中验证字段存在：`\d+ table_name`
   - 再编写视图 XML

3. ✅ **使用 IDE 检查**：
   - 安装 Odoo 插件（如 VSCode 的 Odoo Snippets）
   - 使用 `diagnostics` 工具检查语法错误

## 7. 多公司数据隔离问题

### 错误表现
- 用户能看到其他公司的数据
- 创建记录时 `company_id` 为空
- 跨公司操作被拒绝

### 预防措施
1. ✅ **模型定义必须包含**：
   ```python
   class YourModel(models.Model):
       _name = 'your.model'
       _check_company_auto = True  # 自动检查 company_id
       
       company_id = fields.Many2one(
           'res.company',
           string='公司',
           required=True,
           default=lambda self: self.env.company,
       )
   ```

2. ✅ **关联字段必须检查公司**：
   ```python
   partner_id = fields.Many2one(
       'res.partner',
       string='客户',
       check_company=True,  # 确保 partner 属于同一公司
   )
   ```

3. ✅ **记录规则**：
   ```xml
   <record id="rule_your_model_company" model="ir.rule">
       <field name="name">Your Model: multi-company</field>
       <field name="model_id" ref="model_your_model"/>
       <field name="domain_force">
           ['|', ('company_id', '=', False), ('company_id', 'in', company_ids)]
       </field>
   </record>
   ```

## 8. 缓存问题导致的"改了代码不生效"

### 错误表现
- 修改了 Python 代码，重启后没有变化
- 修改了视图，刷新页面还是旧的
- 修改了 JS/CSS，浏览器显示旧版本

### 解决方案

#### Python 代码缓存
```bash
# 清除 Python 字节码
find . -type d -name __pycache__ -exec rm -rf {} +
find . -name "*.pyc" -delete

# 使用开发模式重启
./odooctl.sh dev-restart
```

#### 视图缓存
```bash
# 清除所有缓存并重启
./odooctl.sh restart clean
```

#### 浏览器缓存
```
# Mac
Cmd + Shift + Delete → 清除缓存

# Windows/Linux  
Ctrl + Shift + Delete → 清除缓存

# 强制刷新
Cmd + Shift + R (Mac)
Ctrl + Shift + R (Windows/Linux)
```

### 预防措施
1. ✅ **开发时使用 `--dev=all` 模式**：
   ```bash
   ./odoo-bin -c odoo.conf --dev=all
   ```
   这会自动重载 Python 代码和 XML 视图

2. ✅ **修改视图后升级模块**：
   ```bash
   ./odooctl.sh start -u module_name
   ```

3. ✅ **浏览器开发者工具**：
   - 打开 Network 标签
   - 勾选 "Disable cache"
   - 保持开发者工具打开状态

## 9. 权限和安全规则错误

### 错误表现
- Access Denied
- You are not allowed to access this document
- RPC_ERROR: Access rights error

### 常见原因
1. **缺少 `ir.model.access.csv`**
2. **记录规则过于严格**
3. **字段级别权限限制**

### 预防措施
1. ✅ **每个模型必须有访问权限**：
   ```csv
   id,name,model_id:id,group_id:id,perm_read,perm_write,perm_create,perm_unlink
   access_your_model_user,your.model.user,model_your_model,base.group_user,1,1,1,1
   access_your_model_manager,your.model.manager,model_your_model,base.group_system,1,1,1,1
   ```

2. ✅ **测试权限**：
   ```python
   # 以普通用户身份测试
   user = self.env.ref('base.user_demo')
   record = self.env['your.model'].with_user(user).create({...})
   ```

3. ✅ **避免滥用 `sudo()`**：
   - 只在必要时使用
   - 使用后立即切换回普通权限
   - 在注释中说明原因

## 10. 开发流程最佳实践

### 修改代码的正确流程

1. **修改前**：
   ```bash
   # 创建功能分支
   git checkout -b feature/your-feature
   
   # 确认当前状态
   ./odooctl.sh status
   ```

2. **修改代码**：
   - 先修改模型（.py）
   - 再修改视图（.xml）
   - 最后修改 assets（.js/.scss）

3. **测试修改**：
   ```bash
   # 升级模块
   ./odooctl.sh start -u module_name
   
   # 检查日志
   tail -f odoo.log | grep -E "ERROR|WARNING"
   
   # 清除浏览器缓存并测试
   ```

4. **提交前检查**：
   ```bash
   # 检查语法
   python3 -m py_compile addons-custom/module_name/**/*.py
   
   # 检查 XML
   xmllint --noout addons-custom/module_name/**/*.xml
   
   # 检查 manifest
   python3 -c "import ast; ast.parse(open('addons-custom/module_name/__manifest__.py').read())"
   ```

### 调试技巧

1. **使用日志**：
   ```python
   import logging
   _logger = logging.getLogger(__name__)
   
   _logger.info("调试信息: %s", variable)
   _logger.warning("警告: %s", message)
   _logger.error("错误: %s", error)
   ```

2. **使用 pdb 断点**：
   ```python
   import pdb; pdb.set_trace()
   ```

3. **检查 SQL 查询**：
   ```python
   # 在 odoo.conf 中启用
   log_level = debug_sql
   ```

## 11. 总结：错误预防检查清单

### 代码提交前必查项

- [ ] `__manifest__.py` 中的 `depends` 是否完整
- [ ] Assets 路径是否使用模块相对路径（不含 `addons-custom/`）
- [ ] 所有模型是否有 `ir.model.access.csv` 权限定义
- [ ] 多公司模型是否设置了 `_check_company_auto = True`
- [ ] 启动脚本是否移除了硬编码的 `--addons-path`
- [ ] 是否清除了临时测试脚本和文件
- [ ] 浏览器缓存是否已清除
- [ ] 日志中是否有 ERROR 或 WARNING

### 遇到错误时的排查顺序

1. **查看日志**：`tail -100 odoo.log | grep -E "ERROR|Traceback"`
2. **检查数据库**：是否有"幽灵"记录（ir_attachment, ir_asset）
3. **检查配置**：启动脚本是否覆盖了配置文件
4. **清除缓存**：`./odooctl.sh restart clean`
5. **升级模块**：`./odooctl.sh start -u module_name`
6. **清除浏览器缓存**：Cmd/Ctrl + Shift + Delete

### 寻求帮助时应提供的信息

1. 完整的错误日志（包括 Traceback）
2. 相关的代码片段
3. 已尝试的解决方法
4. Odoo 版本和模块版本
5. 复现步骤

---

**记住：90% 的错误都是因为缓存、路径、依赖这三个问题。遇到问题先检查这三项！**
