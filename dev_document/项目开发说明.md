# 雪茄威士忌品牌多门店 ERP 开发说明（Odoo 18.0）

> 文档目标：将品牌方和门店运营需求转化为可落地的 Odoo 18.0 模块规范，指导开发、测试与交付。  
> 文档结构：业务背景 → 角色权限 → 模块说明 → 数据模型 → 业务流程 → 报表示例 → 接口与扩展 → 里程碑。

---

## 1. 业务背景与价值诉求

### 1.1 品牌方定位
- 品牌方负责统一品牌形象、商品策略、会员总览、众筹项目审核。  
- 加盟门店高度自治，品牌方不干涉门店日常：采购、库存、员工均独立管理。  
- 品牌方需要跨店掌握会员、众筹与业绩，确保扩张透明合规。  

### 1.2 门店诉求
- 独立进货、自行管理供应商、库存、人员、提成、财务。  
- 服务客户、调酒师、桌台运营等高频流程需高效友好。  
- 支持同一投资人旗下多店的资源互通（库存调拨、会员共享）。  

### 1.3 系统目标
1. 多公司隔离 + 互通组共享，既保留自治又支持集团管理。  
2. 批次库存 + 陈化管理，贴合雪茄特性。  
3. 全面覆盖门店业务：库存、供应商、提成、财务、客户、众筹等。  
4. 前后台全中文界面、移动友好、支持平板吧台使用。

## 2. 角色与权限模型

| 角色 | 所属公司 | 权限概要 |
| --- | --- | --- |
| 品牌超级管理员 | 品牌总部 | 全局配置、互通组维护、全量会员/众筹可见 |
| 品牌运营 | 品牌总部 | 品牌商品模板、众筹审核、全量只读报表 |
| 门店老板/店长 | 门店公司 | 完整门店运营权限、互通调拨审批 |
| 门店仓管 | 门店公司 | 批次入库、盘点、报损、库存报表 |
| 门店财务 | 门店公司 | 交易流水、提成结算、报销/分红执行 |
| 门店员工 | 门店公司 | 点单、查看个人业绩、会员服务（本店） |
| 调酒师 | 门店公司 | 调酒任务看板、个人提成实时查看 |
| 侍茄师 | 门店公司 | 雪茄推荐、陈化批次管理、参与提成分配 |
| 会员 / 投资人 | Portal（多公司） | 会员服务、众筹投资、个人消费记录 |

**权限要点**  
- 所有业务模型默认 `company_id` 隔离。  
- 互通组（`store.link.group`）定义共享范围：会员 / 库存 / 财务。  
- 门店端可查看会员完整联系方式，导出功能受门店权限控制；品牌方掌握全量会员数据。  
- 众筹合同附件、投资金额受品牌方与项目发起店长限制。

## 3. 核心模块说明

### 3.1 基础平台（`brand_core`）
- 多公司初始化脚本；门店与品牌公司建立父子关系。  
- 互通组模型：`store.link.group`，包含共享类型、成员门店、负责人。  
- 门店扩展字段：所属老板（`store.owner`）、陈化仓配置、默认互通组。  
- 权限组定义、菜单骨架。

### 3.2 库存与陈化（`store_inventory`）
- **批次模型** `store.inventory.batch`：  
  - 关键字段：商品、供应商、进货价、初始数量、现库存、陈化开始日期、陈化天数（计算字段）、仓库/库位。  
  - 状态：草稿/在库/调拨中/报损/售罄。  
  - 批次编号使用序列 `store.inventory.batch` 自动生成，支持跨公司唯一。  
- **入库流程**：入库单 → 指定批次信息 → 生成库存移动、财务成本。  
- **盘点/报损/调拨**：均需记录批次、原因、审批链（店长）。  
- **陈化看板**：按陈化天数区间（<30、31-90、>90、>180、>365）高亮显示，陈化无自然结束时间，售罄即完结。  
- **环境记录**：默认不采集温湿度，可留接口供未来硬件对接。  
- **分类库存 & 总览报表**：按分类/状态/仓库统计库存，导出 Excel。  
- **权限控制**：通过记录规则限制库存批次仅在所属公司可见，配合存取权限表。  

### 3.3 供应商管理（`store_supplier`）
- 门店私有供应商档案：基础信息、付款方式、评分、合作历史。  
- 供应商与批次关联；统计供货额、平均交期、质量问题。  
- 支持供应商黑名单、跟进提醒。

### 3.4 提成激励（`store_commission`）
- `store.commission.rule`：规则类型（商品/分类/充值/套餐）、触发条件、提成方式（比例/固定/阶梯）。  
- 指定适用员工（岗位、个人、团队）。  
- 订单必须绑定责任员工，系统默认当前操作人；单笔订单仅允许一个责任员工。  
- 支持调酒师、侍茄师多维提成规则，可按杯数、金额、固定额设定，门店可自定义阶梯周期（日/周/月）。  
- 销售提成与收款到账挂钩，退款或赊销回滚时自动冲减提成。  
- 提成发放：财务确认→状态更新→同步个人业绩，保留调整原因。  
- 提成报表：按员工/规则/时间统计。

### 3.5 财务管理（`store_finance`）
- 交易流水模型 `store.account.transaction`：类别（销售/充值/退款/报损/调拨补差）、金额、支付渠道。  
- 关联订单、库存、提成，确保闭环，用于门店内部对账而非正式会计凭证。  
- 日结/周结/月结报表；导出对账单。  
- 品牌方只读视图，用于掌握整体经营情况。  

### 3.6 吧台运营 + 调酒师工作台（`store_bar`）
- 桌台模型：状态（空闲/占用/结账）、当前订单、服务人员。  
- 点单界面（OWL）：支持套餐组合、快捷搜索、扫码点单、库存实时校验。  
- 套餐仅包含商品，任一商品缺货即禁止下单，提示仓管补货。  
- 调酒师工作台：  
  - 待调制列表（桌台、商品、备注、服务员）。  
  - 今日完成杯数、提成金额、历史查询。  
  - 平板友好界面，支持操作声音提醒。  
- 套餐组合 `store.combo`：设置套餐项与优惠价，订单一键添加。

### 3.7 客户服务与投资管理（`store_member` / `brand_member`）
- 扩展 `res.partner`：以单一客户档案承载会员与投资人角色，字段包含等级、偏好标签、忌讳、首次来源门店、投资偏好、是否允许参与众筹。  
- 会员余额/充值/消费及众筹投资记录在同一档案下维护；互通组内余额共享，不需额外结算。  
- 门店仅可见本店客户，或通过手机号主动添加的会员；投资信息仅对品牌方与所属门店可见。  
- 品牌方可见全量会员、跨店消费与投资轨迹，可按消费额定义等级阈值并自动升级。  
- 会员画像：消费趋势、常点产品、陈化偏好、投资参与度。  
- 通知策略：生日提醒、陈化推荐、众筹推送（需品牌审核）。  
- **权限控制**：员工仅能查看本公司或来源门店的会员档案，品牌方可全局查看。  

### 3.8 个人业绩（`store_performance`）
- 员工仪表盘：销售额、订单数、提成、完成率。  
- 支持员工目标设置、提醒、导出证明。  
- 与提成模块联动：查看提成来源、规则、发放状态。  

### 3.9 众筹扩张（`store_crowdfunding`）
- 申请流程：门店提交项目（合同、地址、面积、筹资额、分红方式、历史业绩）。  
- 品牌方审核（评论、退回、通过），审批日志保留。  
- 项目发布：Portal 端展示项目信息、业绩简报、投资条款。  
- 投资流程：会员签署协议、出资、生成 `store.crowdfunding.investment`。  
- 募集期最长 60 天，未达目标可由门店修改后重新提交。  
- 分红结算：依据项目设定的分红规则自动计算计划，财务执行并记录。  
- 项目状态：草稿/审核中/募集中/执行中/已结项；未通过审核的版本对会员隐藏。  

### 3.10 数据互通与共享（`integration_shared`）
- 互通组配置：仅同一老板旗下门店可加入，同组内定义共享维度（库存、会员、财务）与可见范围。  
- 库存调拨审批流：发起申请 → 互通组审批 → 库存更新 → 财务清算；不同老板间禁止调拨。  
- 共享会员余额：互通组内部消费时自动生成内部结算凭证。  
- API 扩展：预留第三方支付、短信、BI 等接口（后续迭代）。  
- 附件与合同支持品牌水印策略，访问留痕并可按品牌配置保留期限。

## 5. 业务流程（文字流程图）

1. **批次入库**：仓管创建入库单 → 录入批次信息（价格、陈化） → 审批 → 更新库存/财务 → 生成陈化记录。  
2. **门店点单**：服务员/调酒师选择桌台并确认责任员工 → 选择商品/套餐（库存不足即阻止下单）→ 生成订单 → 扣减批次库存 → 提成记录生成。  
3. **提成结算**：提成日志汇总（含退款冲减）→ 财务审核（可调整并记录原因）→ 标记已发放 → 员工个人业绩同步。  
4. **会员互通消费**：互通组门店识别会员 → 校验余额 → 下单减余额 → 自动创建内部清算凭证；非互通门店无权访问。  
5. **库存调拨**：互通组内门店申请调拨 → 审批通过 → 库存双方同步 → 财务记录调拨金额；跨老板门店禁止申请。  
6. **众筹项目**：门店提交申请 → 品牌审核（通过/驳回）→ 发布（募集期<=60 天）→ 会员投资 → 自动生成分红计划 → 分红执行 → 项目结项归档。

## 6. 报表与仪表盘示例

1. **门店库存总览**：库存数量、陈化时长、滞销预警。  
2. **供应商表现**：采购额、平均交期、评价。  
3. **提成分析**：按员工/规则/时间统计提成成本与销售额。  
4. **财务日报**：销售额、充值、退款、报损、净流水。  
5. **桌台运营**：翻台率、客单价、平均停留时间。  
6. **会员画像**：等级分布、消费频次、陈化偏好、互通组贡献。  
7. **众筹仪表盘**：项目进度、募集金额、分红执行情况。  

可使用 Odoo Spreadsheet、Pivot、Graph 结合自定义控件呈现。

## 7. API 与扩展规划

- **支付对接**：预留 `/payment/store/callback` 接口，支持第三方支付回调。  
- **短信/邮件通知**：封装统一的消息中心，便于接入阿里云短信、Sendgrid 等。  
- **预约系统集成**：预留桌台预约接口 `/api/store/table_reservation`。  
- **BI 导出**：提供 CSV/Excel 导出，会计科目同步接口。  

所有外部接口需具备 Token 认证、请求日志、安全限制。

## 8. 项目管理与质量保证

### 8.1 里程碑（与 PLAN 对应）
- M1：多公司框架 + 核心库存模块 + 供应商管理。  
- M2：提成激励 + 财务管理 + 个人业绩。  
- M3：吧台运营 + 调酒师工作台 + 会员管理。  
- M4：互通组共享 + 品牌方总览 + 众筹模块上线。  
- M5：测试、优化、第三方集成、部署文档。  

### 8.2 测试策略
- 单元测试覆盖模型与关键业务逻辑（>80%）。  
- 多公司、多互通组集成测试，确保隔离与共享正确。  
- 性能测试：批次库存、提成计算、众筹查询采用模拟大数据。  
- 安全测试：权限、审计、附件访问。  

### 8.3 运维与监控
- cron 定时任务：陈化天数更新、分红提醒、提成结算。  
- 日志监控：库存/财务/众筹关键操作进入审计日志。  
- 备份策略：每日数据库备份、附件备份，支持快速恢复。

## 10. 门店业务场景与用户故事

### 10.1 库存管理
- **用户故事**  
  - 作为门店仓管，我需要按批次录入进货价格、供应商和陈化开始日期，以便后续准确核算毛利。  
  - 作为店长，我希望在库存总览中快速识别即将售罄或陈化达到最佳口感的雪茄批次。  
- **验收要点**  
  - 批次入库界面必须校验必填字段并支持一键复制上一批次配置。  
  - 库存盘点/报损可按批次调整数量并写入审批日志。  
  - 陈化看板需按陈化天数分层（<30、31-90、91-180、181-365、>365 天），支持导出，售罄后自动归档陈化记录。  

### 10.2 供应商管理
- **用户故事**  
  - 作为门店采购，我需要维护各自供应商的合同附件、付款方式及评分。  
- **验收要点**  
  - 供应商列表仅对所属门店可见；品牌方只读汇总。  
  - 批次与供应商实现双向追溯，导出采购历史。  

### 10.3 提成激励
- **用户故事**  
  - 作为店长，我要按产品或分类配置阶梯提成，让不同员工有差异化激励。  
  - 作为调酒师/侍茄师，我希望订单绑定我的账号并按规则自动计算提成，包括调酒杯数奖励。  
- **验收要点**  
  - 提成规则支持商品、分类、套餐、充值等多维组合，并允许设置阶梯周期（日/周/月）。  
  - 订单仅能绑定一个责任员工，退款或赊销冲减时同步回滚提成；财务调整需记录原因。  

### 10.4 财务管理
- **用户故事**  
  - 作为门店财务，我需要每日核对销售、充值和退款流水，确保余额准确。  
- **验收要点**  
  - 交易流水自动分类（现金、储值、POS、第三方），生成门店级内部对账单。  
  - 品牌方可查看汇总报表但不可修改门店原始流水与提成结算。  

### 10.5 吧台运营与调酒师工作台
- **用户故事**  
  - 作为服务员，我希望在点单时选择桌台、员工、套餐，系统自动扣减库存。  
  - 作为调酒师，我需要查看当天所有待调制酒水，并获取完成数及提成金额。  
- **验收要点**  
  - 桌台状态实时更新（开台/占用/结账），操作日志可追溯。  
  - 调酒师界面提供语音/视觉提醒，支持平板横屏显示。  
  - 套餐中任一商品缺货时阻止下单并提示补货或改选其他批次。  

### 10.6 客户服务与会员互通
- **用户故事**  
  - 作为门店员工，我要快速绑定会员手机号，查看本店消费与偏好。  
  - 作为品牌方运营，我需看到全网会员来源门店及跨店消费情况。  
- **验收要点**  
  - 互通组门店在会员详情页展示共享余额及消费记录，非互通门店无权访问。  
  - 会员新增或修改操作写入审计日志，门店端可查看完整联系方式，导出须有权限。  

### 10.7 个人业绩
- **用户故事**  
  - 作为员工，我需要查看当月销售额、提成达成率及目标提醒。  
- **验收要点**  
  - 系统根据提成发放状态区分“待发放/已发放”，员工端实时更新。  
  - 支持导出个人业绩报表供店长绩效评估。  

### 10.8 众筹扩张
- **用户故事**  
  - 作为门店老板，我要提交众筹申请并附上合同、募资金额、分红规则。  
  - 作为会员（亦是潜在投资人），我需读取项目说明、门店历史业绩并完成投资。  
- **验收要点**  
  - 众筹申请须经品牌方审核才对会员开放，所有附件需按品牌水印策略存档。  
  - 募集期最长 60 天，过期未达目标需重新提交；投资完成后自动生成分红计划，状态流程为：草稿→审核中→募集中→执行中→已结项。

## 12. 开发约束与技术实现备注

- 遵循 Odoo 多公司最佳实践，不修改核心模块；所有自定义逻辑放入 `addons-custom`。  
- UI 需提供中文名称与提示，关键界面支持移动端（OWL 或 `web` 控件自适应）。  
- 采用 Odoo 标准模型扩展（继承 `stock`, `sale`, `account`, `hr`, `project` 等）优先，避免重复造轮子。  
- 对批次、提成、众筹等关键流程编写自动化测试与数据校验（避免重复扣减库存、重复发放提成）。  
- 附件与合同需通过附件模型安全存储，生成品牌水印并记录访问日志，保留期限可配置。  
- 互通逻辑仅适用于同一老板门店，应用层需校验并拒绝跨老板调拨。  
- 财务模块定位为运营对账，不输出税务凭证，可保留扩展接口以对接专业财务系统。  
- 当前阶段无需集成温湿度、POS 等硬件；接口预留在后续迭代实现。  
- 已为库存批次与会员档案配置多公司记录规则，并编写单元测试覆盖陈化天数计算与入会日期填充逻辑。
